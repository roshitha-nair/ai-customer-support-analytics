# Data Dictionary

## Overview

This project uses a processed data layer and a DuckDB star schema for customer support analytics.

The processed data outputs are generated by the cleaning, sentiment analysis, topic modeling, and dissatisfaction-risk pipelines. These outputs are integrated into the DuckDB star schema through reproducible loading scripts.

The analytical star schema consists of four dimension tables and one fact table:

- `dim_category`
- `dim_channel`
- `dim_priority`
- `dim_date`
- `fact_ticket`

## Processed Data Outputs

### `customer_support_tickets_cleaned.csv`

Cleaned and feature-engineered ticket-level dataset.

| Column | Description |
|---|---|
| `Ticket ID` | Unique identifier for each customer support ticket. |
| `Customer Age` | Age of the customer associated with the ticket. |
| `Customer Gender` | Recorded customer gender. |
| `Product Purchased` | Product associated with the support ticket. |
| `Date of Purchase` | Date of purchase associated with the ticket. Used as the project's available date dimension. |
| `Ticket Type` | Category or type of customer support request. |
| `Ticket Subject` | Subject line or short summary of the support ticket. |
| `Ticket Description` | Original ticket description from the source dataset. |
| `Ticket Status` | Recorded status of the support ticket. |
| `Resolution` | Recorded resolution information when available. |
| `Ticket Priority` | Assigned priority level for the ticket. |
| `Ticket Channel` | Customer support channel used for the ticket. |
| `First Response Time` | Recorded timestamp associated with the first response when available. |
| `Time to Resolution` | Recorded timestamp associated with resolution when available. |
| `Customer Satisfaction Rating` | Observed customer satisfaction rating when available. |
| `Cleaned Ticket Description` | Cleaned version of the ticket description used for downstream text analysis. |
| `Has First Response` | Indicator showing whether a first-response timestamp is available. |
| `Is Resolved` | Indicator showing whether the ticket is recorded as resolved. |
| `Has CSAT` | Indicator showing whether a customer satisfaction rating is available. |
| `is_dissatisfied` | Observed dissatisfaction target derived from CSAT: `1` for CSAT less than or equal to 2, `0` for CSAT greater than or equal to 3, and missing when CSAT is unavailable. |

### `ticket_sentiment.csv`

Ticket-level sentiment output generated by the pretrained sentiment classification pipeline.

| Column | Description |
|---|---|
| `ticket_id` | Unique ticket identifier used to join sentiment results to the analytical dataset. |
| `sentiment_label` | Model-predicted sentiment class. |
| `sentiment_score` | Model confidence score associated with the predicted sentiment output. |

Sentiment outputs are model-derived analytical features and should not be treated as ground truth.

### `customer_support_topics.csv`

Ticket-level topic assignments generated through BERTopic and subsequent human-readable labeling.

| Column | Description |
|---|---|
| `Ticket ID` | Unique ticket identifier used to join topic assignments to the analytical dataset. |
| `topic_id` | Model-generated BERTopic identifier. This value is categorical and should not be interpreted as ordinal severity or priority. |
| `topic_label` | Human-readable interpretation assigned to the discovered topic. |

Topic assignments are exploratory analytical features rather than ground-truth classifications.

### `ticket_dissatisfaction_risk.csv`

Ticket-level predicted dissatisfaction-risk output generated using the saved dissatisfaction-risk model.

| Column | Description |
|---|---|
| `ticket_id` | Unique ticket identifier used to join risk scores to the analytical dataset. |
| `dissatisfaction_risk_score` | Model-generated probability-like score representing predicted dissatisfaction risk. Higher values indicate higher predicted risk. |

The dissatisfaction-risk score is a prioritization signal and should not be interpreted as a definitive dissatisfaction classification.

## Fact Table

### `fact_ticket`

The central ticket-level fact table. Each row represents one customer support ticket.

| Column | Data Type | Description |
|---|---|---|
| `ticket_id` | `BIGINT` | Unique identifier for the customer support ticket. |
| `category_key` | `INTEGER` | Foreign key to `dim_category`. |
| `channel_key` | `INTEGER` | Foreign key to `dim_channel`. |
| `priority_key` | `INTEGER` | Foreign key to `dim_priority`. |
| `purchase_date_key` | `INTEGER` | Foreign key to `dim_date`, based on `Date of Purchase`. |
| `customer_age` | `BIGINT` | Age of the customer associated with the ticket. |
| `customer_gender` | `VARCHAR` | Recorded customer gender. |
| `product_purchased` | `VARCHAR` | Product associated with the ticket. |
| `ticket_subject` | `VARCHAR` | Subject line or short summary of the support ticket. |
| `cleaned_ticket_description` | `VARCHAR` | Cleaned ticket description used for text-based analysis. |
| `ticket_status` | `VARCHAR` | Recorded support ticket status. |
| `resolution` | `VARCHAR` | Recorded ticket resolution information when available. |
| `first_response_time` | `TIMESTAMP` | Recorded first-response timestamp when available. |
| `time_to_resolution` | `TIMESTAMP` | Recorded resolution-related timestamp when available. |
| `customer_satisfaction_rating` | `DOUBLE` | Observed customer satisfaction rating when available. |
| `has_first_response` | `BIGINT` | Indicator showing whether a first-response timestamp is available. |
| `is_resolved` | `BIGINT` | Indicator showing whether the ticket is recorded as resolved. |
| `has_csat` | `BIGINT` | Indicator showing whether a customer satisfaction rating is available. |
| `is_dissatisfied` | `BIGINT` | Observed dissatisfaction target derived from available CSAT values. `1` indicates CSAT less than or equal to 2; `0` indicates CSAT greater than or equal to 3; missing indicates that CSAT was unavailable. |
| `sentiment_label` | `VARCHAR` | Model-predicted sentiment classification. |
| `sentiment_score` | `DOUBLE` | Model confidence score associated with the sentiment output. |
| `topic_id` | `INTEGER` | Model-generated topic identifier from BERTopic. |
| `topic_label` | `VARCHAR` | Human-readable interpretation of the assigned topic. |
| `dissatisfaction_risk_score` | `DOUBLE` | Model-generated predicted dissatisfaction-risk score for ticket prioritization. Higher values indicate higher predicted risk. |

## Observed vs. Model-Derived Fields

Two fields should be clearly distinguished in downstream analysis:

### `is_dissatisfied`

`is_dissatisfied` is an observed, CSAT-derived outcome available only for tickets with a recorded customer satisfaction rating.

- `1` = dissatisfied, CSAT less than or equal to 2
- `0` = not dissatisfied, CSAT greater than or equal to 3
- Missing = no CSAT observation available

This field was used as the supervised modeling target.

### `dissatisfaction_risk_score`

`dissatisfaction_risk_score` is a model-generated prediction available for all tickets in the final analytical population.

It is intended to support prioritization and risk-based analysis. It should not be interpreted as observed customer dissatisfaction or as a definitive classification.

## Data Modeling Notes

- `fact_ticket` contains one row per unique ticket.
- Dimension relationships are enforced through foreign keys.
- AI-derived fields are integrated using validated ticket-level joins.
- The date dimension is based on `Date of Purchase`, not ticket creation.
- Timestamp-derived resolution-duration metrics are not created because the available timestamp ordering is not sufficiently reliable.
- Topic IDs are categorical model outputs and should not be interpreted as ordered values.
- Sentiment, topic, and dissatisfaction-risk outputs are model-derived analytical features and should be interpreted alongside their documented limitations.
