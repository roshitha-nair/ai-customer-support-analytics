# Dissatisfaction-Risk Model Card

## Model Overview

This model estimates the risk that a customer support ticket is associated with customer dissatisfaction.

The predictive target is `is_dissatisfied`, derived from observed Customer Satisfaction Rating values:

- `1` = Customer Satisfaction Rating less than or equal to 2
- `0` = Customer Satisfaction Rating greater than or equal to 3

The model is trained only on tickets with an observed Customer Satisfaction Rating.

The resulting model can generate dissatisfaction-risk probabilities for tickets regardless of whether an observed Customer Satisfaction Rating is available.

## Model

- Model type: Gradient Boosting Classifier
- Classification threshold: 0.30
- CSAT-observed training population: 2,769 tickets
- Model fitting set: 2,215 tickets
- Evaluation set: 554 tickets
- Random state: 42

### Model Artifact

The fitted preprocessing and classification pipeline is saved as:

`models/dissatisfaction_risk_model.pkl`

The selected classification threshold and related metadata are stored separately in:

`models/dissatisfaction_risk_threshold.json`

## Input Features

The model uses the following features:

### Categorical features

- Ticket Priority
- Ticket Channel
- sentiment_label
- topic_id

### Numeric feature

- sentiment_score

Categorical features are one-hot encoded.

`topic_id` is treated as a categorical feature because BERTopic topic identifiers are model-generated labels and do not represent an ordinal scale.

## Target

The model predicts:

`is_dissatisfied`

Class definitions:

- `0` = Not dissatisfied
- `1` = Dissatisfied

The target is available only for tickets with an observed Customer Satisfaction Rating.

## Performance

Evaluation was performed using a stratified 80/20 train/test split of the CSAT-observed population.

At the selected classification threshold of 0.30:

- Accuracy: 0.4188
- Dissatisfied precision: 0.3988
- Dissatisfied recall: 0.9136
- Dissatisfied F1-score: 0.5552

The selected threshold prioritizes recall for dissatisfied tickets. This allows the model to identify a large proportion of potentially dissatisfied customers while producing a substantial number of false-positive risk flags.

The model should therefore be used as a prioritization signal rather than as a definitive classification of customer dissatisfaction.

## Model Selection

Three predictive approaches were evaluated:

- Logistic Regression
- Gradient Boosting
- Logistic Regression with balanced class weights

Gradient Boosting achieved the highest observed Average Precision:

- Gradient Boosting: 0.4169
- Logistic Regression: 0.3995
- Balanced Logistic Regression: 0.3988

Threshold evaluation was then performed for the Gradient Boosting model.

A threshold of 0.30 produced the strongest observed dissatisfied-class F1-score among the evaluated thresholds:

- Precision: 0.3988
- Recall: 0.9136
- F1-score: 0.5552

The threshold was selected using the same test set used for model evaluation. The threshold-specific performance should therefore be considered exploratory and should be validated on an independent dataset before production deployment.

## Feature Importance

Feature importance from the fitted Gradient Boosting model indicates that `sentiment_score` is the dominant transformed feature, with an importance of approximately 0.573.

Other features, including ticket priority, ticket channel, and topic assignments, have substantially smaller individual importance values.

Feature importance values describe relative contribution within the fitted model and do not establish causal relationships.

## Limitations

- The model is trained only on the subset of tickets with observed Customer Satisfaction Ratings.
- The full dataset contains many tickets without an observed target, so the training population may not fully represent the broader ticket population.
- Sentiment features are derived from a pretrained general-domain sentiment model and have documented domain-mismatch limitations.
- Topic assignments are exploratory outputs generated by BERTopic and should not be treated as ground-truth issue categories.
- The available structured feature set provides limited separation between dissatisfied and non-dissatisfied tickets.
- The selected threshold substantially favors recall and produces many false-positive dissatisfaction-risk flags.
- Threshold-specific performance was selected using the test set and requires validation on independent data.

## Intended Use

The model is intended to support analytical prioritization of customer support tickets that may be at higher risk of dissatisfaction.

Potential uses include:

- Prioritizing tickets for proactive review
- Identifying groups of tickets that may require additional support attention
- Supporting operational analysis of dissatisfaction risk patterns

The model is not intended to replace human judgment or to make automated customer-impact decisions without additional validation.
